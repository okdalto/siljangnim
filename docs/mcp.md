# 에이전트 연결하기 (Claude Code, Codex 등)

[English](en/mcp.md)

Claude Code나 Codex 같은 에이전트에 실장님을 붙이면, 에이전트와 대화하면서 결과를 실장님 뷰어에서 바로 볼 수 있습니다.
에이전트는 씬을 만들고 고치고, 화면을 캡처해 직접 확인합니다.

## 설치

[Node.js 22 이상](https://nodejs.org)이 필요합니다.

**Claude Code** — 터미널에서:

```bash
claude mcp add siljangnim -- npx -y siljangnim-mcp@latest
```

또는 Claude Code에 "실장님 MCP 서버를 설치해 줘: `claude mcp add siljangnim -- npx -y siljangnim-mcp@latest`"라고
붙여 넣으세요. 설치한 뒤에는 Claude Code를 다시 시작해야 합니다.

**Codex** — 일반 터미널에서 한 줄을 실행하세요:

```bash
npx -y siljangnim-mcp@latest setup codex
```

Node.js 22 이상과 Codex CLI를 확인하고, 서버 등록·등록 결과 확인·MCP 연결 검사·테스트 뷰어 열기를 자동으로 처리합니다.
설정 파일을 직접 편집할 필요는 없습니다. 긴 호출은 45초 안에 추적 ID를 반환하므로 `tool_timeout_sec = 120`은 필수가 아닙니다.
검사 후 임시 연결은 종료됩니다. 테스트 탭을 닫고 Codex를 완전히 종료한 뒤 다시 실행하세요.
Codex가 서버를 시작하면 뷰어가 자동으로 열립니다. 현재 실행 중인 Codex 대화가 연결됐다는 뜻은 아닙니다.

등록은 같은 명령으로 갱신할 수 있습니다. Codex CLI가 없다면 먼저 설치하고 `codex --version`이 실행되는지 확인하세요.
등록 후 뷰어 검사만 실패했다면 등록은 유지됩니다. 출력된 주소를 열거나 문제를 해결한 뒤 같은 명령을 다시 실행하세요.
에이전트의 쓰기 권한 제한으로 등록이 실패하면 일반 터미널에서 실행하세요.

**Cursor, Claude 데스크톱 앱, Windsurf 등** — 클라이언트의 MCP 설정 파일에:

```json
{
  "mcpServers": {
    "siljangnim": { "command": "npx", "args": ["-y", "siljangnim-mcp@latest"] }
  }
}
```

지우려면 `claude mcp remove siljangnim`(Codex 등은 설정에서 해당 항목 삭제).

## 쓰는 법

- 에이전트에게 "siljangnim으로 …를 만들어 줘"라고 하세요. 처음 도구를 쓸 때 뷰어(`http://localhost:47823`)가 열립니다. Chrome이나 Edge(Brave, Chromium도 됨)가 있으면 탭과 주소창 없는 앱 창으로, 없으면 기본 브라우저의 탭으로 엽니다.
- 대화는 에이전트 쪽에서 하고, 뷰어의 **Activity** 탭에서 에이전트가 한 일을 볼 수 있습니다. 컨트롤, 히스토리, 에셋, 녹화는 평소처럼 씁니다.
- **실장님 데스크톱 앱이 켜져 있으면** 브라우저 대신 그 앱 창이 뷰어가 됩니다. 앱의 프로젝트와 레시피를 그대로 씁니다.
- 오래 걸리는 도구 호출은 추적 ID를 반환합니다. 에이전트는 원래 도구를 다시 실행하지 않고 `viewer_call_status`로 같은 호출의 결과를 이어서 조회합니다. 이 ID는 Python 작업의 `job_status` ID와 다릅니다. 완료된 결과는 10분 동안 보관되며, 이미 조회한 결과는 보관 한도에 도달하면 먼저 정리될 수 있습니다.
- Python 패키지나 프로그램을 실행해야 할 때는 뷰어에 허락을 묻는 카드가 뜹니다. 여러 요청이 동시에 오면 순서대로 표시합니다. 승인 대기 시간이 지나면 아무것도 실행하지 않고 종료하며, 도구를 다시 호출하면 새 승인 카드가 표시됩니다. 자세한 건 [내 컴퓨터에서 도구 실행하기](local-tools.md).
- 프로젝트는 브라우저 저장소에 저장됩니다. 같은 포트로 열어야 이전 프로젝트가 보입니다.

## 옵션

환경 변수로 바꿀 수 있습니다(MCP 설정의 `env`에 넣으세요).

| 변수 | 뜻 |
|---|---|
| `SILJANGNIM_PORT` | 뷰어 포트. 기본 47823. 이미 쓰는 중이면 다른 포트로 열리고, 그때는 이전 프로젝트가 보이지 않습니다. |
| `SILJANGNIM_OPEN_ON_CONNECT=1` | Codex 서버 시작 시 뷰어를 자동으로 엽니다. `setup codex`가 설정합니다. |
| `SILJANGNIM_OPEN=0` | 브라우저를 자동으로 열지 않습니다(주소는 로그에 남습니다). |
| `SILJANGNIM_OPEN_COMMAND` | 뷰어를 열 프로그램(주소를 인자로 받음). 특정 브라우저로 열 때. |
| `SILJANGNIM_APP_WINDOW=0` | 앱 창 대신 기본 브라우저의 탭으로 엽니다. |
| `SILJANGNIM_VIEWER=browser` | 데스크톱 앱이 켜져 있어도 브라우저를 씁니다. |

## 문제 해결

- **뷰어가 안 열려요** — 에이전트에게 "siljangnim 뷰어 열어 줘"라고 하세요. 그래도 안 되면 로그에 찍힌 주소를 직접 여세요.
- **이전 프로젝트가 안 보여요** — 다른 포트로 열렸을 수 있습니다. 47823을 쓰는 다른 프로그램을 끄고 다시 시작하세요.
- **처음 Python 도구를 쓸 때 오래 걸려요** — 처음 한 번 uv와 Python을 `~/.siljangnim/runtime/`에 받습니다.
- **새 버전이 반영되지 않아요** — 설정에 `siljangnim-mcp@latest`로 적혀 있는지 확인하세요.
- **녹화 파일이 두 번째부터 안 받아져요** — 브라우저는 한 페이지에서 저절로 시작되는 다운로드를 여러 번 하지 못하게 막습니다. 뷰어 창을 한 번 누르거나 여러 파일 다운로드를 허용하세요. 녹화본은 받아지지 않아도 프로젝트 에셋에 저장돼 있습니다.
- **뷰어 창이 여러 개 떠요** — 서버가 새로 시작될 때마다 새 창이 열리고, 앞의 창은 다시 연결되지 않습니다. 에이전트가 서버를 다시 띄우지 않게 하고, 남은 창은 닫아도 됩니다.

## 보안

뷰어 서버는 이 컴퓨터(127.0.0.1)에서만 열리고, 실행할 때마다 바뀌는 토큰이 있어야 접속됩니다. 씬 코드는 별도 출처에서
돌아서 프로젝트나 키에 접근하지 못합니다. 네트워크에 노출하지 마세요.
