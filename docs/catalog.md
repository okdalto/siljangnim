# 카탈로그 (6단계)

> 상태: 구현됨 · 2026-10-11. 설계는 [architecture.md](architecture.md#9-카탈로그)에 있다.

에이전트가 기능에 맞는 오픈소스를 고를 때 보는 **메타데이터 목록**이다. 코드는 담지 않는다.

- **위치:** `studio/src/catalog/catalog.json`. 스튜디오에 번들되므로 허브가 없어도, 웹에서도 동작한다.
- **항목:**
  - id, 이름, 저장소, 라이선스, 용도(직접 쓴 한 줄), 태그, 입출력 매체
  - 등급: B 씬 안의 JS, C Python 패키지, D 설치된 프로그램, E GPU/큰 모델
  - 설치 정보: CDN URL, pip 스펙, 또는 프로그램 이름
  - 가중치 라이선스, GPU 필요 여부, 메모
- **처음 항목:** 35개(B 11, C 11, D 6, E 7)를 직접 썼다. 버전 고정값은 npm·PyPI에 실제로 있는지 확인했다(2026-10-11). 최신 버전은 아닐 수 있다. 실제로 동작한 조합은 레시피가 기록한다.
- **도구:**
  - `catalog_search(query, media?, tier?)`: 검색어의 모든 단어가 맞는 항목을 고른다. 이름 > 태그 > 용도 순으로 점수를 매기고, 점수가 같으면 가벼운 등급(B → E)을 먼저 보여 준다.
  - `catalog_get(id)`: 설치·가져오기 방법과 라이선스(가중치 포함)를 보여 준다.
  - 프롬프트: 도구를 고를 때 `catalog_search` → `recipe_search` 순서로 쓴다.
- **index.opensource:** 참고 목록으로 계획했지만, 데이터 사용 조건이 사이트에 적혀 있지 않아 설명문을 옮기지 않았다. 조건을 확인하면 출처를 표기하고 항목을 늘린다. 이건 사람이 결정한다.
- **기여:** 이 파일에 항목을 추가하는 PR을 보낸다. 테스트가 id 중복, 등급별 설치 정보, B 등급 CDN 허용 목록(esm.sh, jsdelivr, unpkg)을 확인한다.
