# M2 계획: v1 핵심 기능을 studio로

> 상태: 진행 중 (1·2·3 완료) · 2026-10
> 전제: [studio.md](studio.md)(M1 구조), 루트 `CLAUDE.md`(지켜야 할 규칙)

## 0. 시작 전에: M1 실기 검증

M1은 Linux 컨테이너에서 목(mock) API로만 검증했다. M2를 시작하기 전에 다음을 확인한다.

1. macOS(Apple Silicon)에서 `npm install` → `npm run check && npm test && npm run smoke`를 실행한다.
2. `npm run dev`로 띄워서 **실제 API 키**로 프롬프트 3~5개를 돌린다. 예: 파도 셰이더, 마우스로 흔드는 반응-확산(핑퐁 버퍼), 레이마칭 구체, 텍스처를 쓰는 씬.
3. 실패 패턴을 기록하고 `agent/prompt.ts`와 도구 설명을 다듬는다. 자주 틀리는 ctx 사용법, 캡처 확인을 건너뛰는지, 같은 수정을 반복하는지를 본다.
4. `npm run dist`로 dmg를 만들고 패키징된 앱의 smoke도 돌린다.

여기서 나온 버그 수정은 M2보다 먼저 한다.

**결과 (2026-10-11, macOS 26 / Apple M5, Node 25, npm 11):**

- 1번 통과. `npm install` 후 `check`, `test`(vitest 19개, pytest 6개), `smoke`(체크 10개, 목 요청 4회) 모두 통과했다. smoke 보고서의 CSP 콘솔 에러 2건은 씬 iframe이 포워더에 접근하려다 막히는 검사(`llmRefusesScene`)에서 나오는 것으로, 의도된 동작이다.
- 4번 통과. `npm run dist`로 `Siljangnim-0.2.0-mac-arm64.dmg`를 만들었다(ad-hoc 서명, 공증 없음). 패키징된 앱으로 돌린 smoke(`SILJANGNIM_APP_PATH=release/mac-arm64/Siljangnim.app/Contents/MacOS/Siljangnim`)도 모든 체크를 통과했다.
- 2번은 GPT(`gpt-6.1-sol`, 브라우저 모드)로 프롬프트 5개를 돌렸다. Claude 키로는 아직 돌리지 않았다.
  - 파도 셰이더: `scene_write → capture → scene_edit → capture`로 끝났다. 캡처를 보고 스스로 다듬었다.
  - 마우스로 휘젓는 반응-확산(핑퐁 버퍼): 첫 `scene_write`가 셰이더 컴파일 에러로 실패했다. 에러 위치가 줄 번호와 발췌로 돌아와서 `scene_edit` 한 번으로 고쳤다. 원인은 GLSL 예약어 `active`를 변수명으로 쓴 것이다.
  - 레이마칭 반사 구체 + 마우스 카메라: 한 번에 성공했다. 휠 줌은 `ctx.canvas`에 리스너를 직접 달았고 cleanup에서 해제했다.
  - 업로드한 이미지를 텍스처로 쓴 천: 비전 블록과 `loadTexture(name)`이 동작했고 방향(flipY)도 맞았다.
  - "아까 반응-확산이 나았다": `history_list → history_restore → capture`로 처리했다.
  - 같은 수정을 반복하거나 캡처 확인을 건너뛴 경우는 없었다.
- 실기 검증에서 찾아 고친 것:
  - 최신 OpenAI 추론 모델은 `/chat/completions`에서 함수 도구를 거부한다("use /v1/responses"). 그래서 GPT(api.openai.com)는 Responses API 어댑터(`agent/llm/responses.ts`)로 바꿨다. 로컬·기타 서버는 Chat Completions를 그대로 쓴다. Responses는 `store: false`이고 reasoning 항목을 턴 사이에 되돌려 보내지 않는다(대화 형식에 자리가 없다).
  - 설정 창을 Claude · GPT · Other로 나눴다. GPT와 Other는 서버의 `/models` 목록에서 모델을 고른다. GPT 목록에서는 날짜 스냅샷, pro/codex, 구형 모델을 뺀다.
  - API 키를 모델 칸에 붙여 넣어도 저장되지 않게 막았다. 이전 버전 설정에 남은 키는 불러올 때 지운다.
- 3번은 프롬프트에 GLSL 예약어 목록을 넣었다. 나머지 동작은 프롬프트를 바꿀 근거가 없었다.

## 작업 순서

에이전트의 수정을 되돌릴 수 있는 안전망부터 만든다. 그다음은 사용 빈도 순이다.

| # | 기능 | 이유 | 상태 |
|---|---|---|---|
| 1 | 버전 히스토리 | 에이전트가 씬을 망쳐도 되돌릴 수 있어야 실험이 편하다 | 완료 |
| 2 | 에셋 업로드 | 이미지·영상·오디오를 쓰는 작업이 많다 | 완료 |
| 3 | 타임라인·키프레임 | 애니메이션과 이후 녹화(M3)의 바탕이다 | 완료 |
| 3.5 | `ask_user` 도구 | 요청이 정말 모호할 때 에이전트가 선택지로 묻는다 | 완료 |
| 4 | 에이전트 패널(확장 컨트롤) | 유니폼 컨트롤만으로 부족한 UI | 선언형 완료, HTML 패널은 2단계 뒤 |
| 5 | WebGPU 백엔드 | compute가 필요한 씬. 수요가 가장 적다 | 2·3단계 뒤로 미룸 |

**진행 (2026-10-11):** 1~4번(HTML 패널 제외)과 `ask_user`를 마쳤고, 이어서 아키텍처 2단계의 외부 에이전트 연결을 브라우저 뷰어로 구현했다([mcp.md](mcp.md)). 이어서 3단계 런타임(C/D 등급)을 구현했다([runtime.md](runtime.md)). 다음은 4단계(레시피), M3, WebGPU다.

**순서 조정 (2026-10-11):** 4번까지 마친 뒤 M3보다 먼저 아키텍처 2·3단계를 진행한다. 2단계는 MCP 서버로, Claude Code·Codex 같은 외부 에이전트가 앱을 조작하고 앱 채팅으로 대화하게 한다. 3단계는 C/D 등급 런타임이다. M3는 대부분 v1 기능을 옮기는 일이고, 오픈소스를 붙이는 쪽이 이 프로젝트의 차별점이기 때문이다. 그다음 4단계(레시피), M3, 5번 WebGPU 순으로 간다.

**UI 원칙:** 최소한의 고정 뼈대(뷰포트, 채팅, 히스토리, 에셋)를 두고, 나머지 UI는 준비해 두되 필수로 띄우지 않는다. 씬과 에이전트가 필요로 할 때만 나타난다(예: Live/Timeline 모드, 선언형 패널).

기능마다 완료 기준은 같다.

- `check`, `test`, `smoke`가 통과한다.
- 로직에 단위 테스트가 있다.
- 에이전트가 쓰는 기능이면 smoke의 목 시나리오에서 실제로 호출해 본다.
- 문서를 갱신하고 커밋을 따로 남긴다.

## 1. 버전 히스토리

- **모델:** 커밋 트리. `{ id, projectId, parentId, createdAt, message, scene, thumbnail?, chatLength }`
  - `scene`은 전체 JSON 스냅샷이다. 씬은 수 KB라 패치·체크포인트 방식은 쓰지 않는다. v1 projectTree의 복잡도를 반복하지 않는다.
  - `chatLength`는 그 시점의 메시지 수다. 대화와 버전을 연결한다.
- **저장:** IndexedDB `versions` 스토어(인덱스 `byProject`). `ProjectStore`의 DB 버전을 2로 올리고 upgrade에서 스토어를 추가한다. 기존 데이터 마이그레이션 테스트를 쓴다.
- **언제 만드나:**
  - 에이전트 실행이 끝났을 때. message는 사용자 프롬프트의 앞부분으로 한다.
  - 사용자가 컨트롤을 만지다 멈췄을 때(디바운스). 직전 버전과 씬이 같으면 만들지 않는다.
- **썸네일:** 버전을 만들 때 `capture`를 256px로 찍어 Blob으로 저장한다. 실패하면 썸네일 없이 저장한다.
- **복원:** 버전을 고르면 그 씬을 적용하고 HEAD를 옮긴다. 이후 변경은 그 버전의 자식이 되어 브랜치가 생긴다.
  - 대화는 append-only이므로 되감지 않는다.
  - 대신 복원할 때 다음 사용자 메시지 앞에 "버전 X로 되돌렸다"는 맥락을 붙인다. 시스템 프롬프트는 바꾸지 않는다.
- **UI:** 오른쪽 패널에 탭 하나(채팅 | 히스토리). 썸네일 목록에 부모 관계를 들여쓰기로 표시하는 정도면 충분하다.
- **도구(선택):** `history_list`, `history_restore`. 에이전트가 "아까 버전이 나았다"를 처리할 수 있게 한다.

**구현 메모 (완료):**

- HEAD는 `ProjectMeta.head`에 둔다. HEAD를 옮겨도 `updatedAt`은 바꾸지 않는다.
- 프로젝트의 첫 씬을 처음 로드할 때 루트 버전("Initial scene")을 만든다. M1에서 만든 프로젝트도 처음 열 때 그 시점 씬이 루트가 된다.
- 컨트롤 변경은 1.5초 동안 멈추면 버전이 된다. 프롬프트 전송·프로젝트 전환·복원 직전에도 즉시 확정한다. 메시지는 "Adjusted Speed, Tint"처럼 바뀐 컨트롤 이름이다.
- 커밋과 복원은 한 큐에서 차례로 실행한다. 그래서 에이전트 실행 중의 복원과 실행 종료 시점의 커밋이 섞이지 않는다.
- 사용자가 패널에서 복원하면 다음 사용자 메시지 앞에 `[Studio note] …` 텍스트 블록을 붙인다(`agent/context.ts`). 채팅 UI는 이 블록을 사용자 말풍선 대신 작은 안내문으로 보여 준다.
- 트리 표시는 이렇다. 첫 자식은 부모와 같은 줄에 이어지고, 이후 자식(복원 뒤에 생긴 브랜치)은 한 단계 들여 쓴다. 브랜치는 부모의 본류보다 먼저 나열한다(`project/history.ts`의 `layoutTree`).
- smoke에서는 목 에이전트가 `history_list`를 호출하고, 실행 뒤 히스토리 탭에 썸네일이 있는 버전 2개가 생기는지 본다. 이어서 첫 버전을 클릭해 원래 씬으로 복원되는지 확인한다.

## 2. 에셋 업로드

- **입력:** 뷰포트나 채팅에 드래그 앤 드롭, 또는 파일 선택. 이미지, 영상(mp4/webm), 오디오, 폰트, SVG, JSON/텍스트, glb/obj를 받는다.
- **저장:** `files` 스토어에 `assets/<name>` Blob으로 둔다.
  - 이름이 겹치면 `name-2.png`처럼 바꾼다.
  - 크기 상한은 우선 200MB/파일로 하고 UI에서 거절한다.
- **런타임 전달:** 이미 지원한다(`load`의 `assets` → `ctx.assets[name]` blob URL). 씬을 로드할 때 프로젝트 에셋 전체를 넘긴다. 큰 에셋이 많아지면 나중에 씬이 참조하는 것만 넘기도록 최적화한다.
- **메타데이터:** 업로드할 때 가볍게 분석한다. 이미지는 크기, 영상·오디오는 길이와 해상도, 3D는 정점 수다. v1 `assetProcessor.js`에서 필요한 부분만 가져온다.
- **에이전트에게:**
  - `asset_list` 도구: 이름, 종류, 크기, 메타데이터를 돌려준다.
  - 이미지를 프롬프트와 함께 올리면 축소본(최대 1024px)을 사용자 메시지에 image 블록으로 붙인다(비전).
  - 텍스트·JSON은 `asset_read`로 읽는다(크기 제한).
- **ctx:** `ctx.utils.loadTexture(name)`는 이미 에셋 이름을 받는다.
  - 영상 텍스처 헬퍼(`createVideoTexture(name)` → 매 프레임 `update()`)를 추가한다.
  - glTF/OBJ 로더는 B등급 온디맨드 원칙에 따라 에이전트가 `ctx.utils.import`로 받아 쓰게 두고, 프롬프트에 방법을 적는다.
- **보안:** 에셋은 Blob으로만 넘긴다. SVG는 `<img>`/텍스처로만 쓰고 DOM에 삽입하지 않는다.

**구현 메모 (완료):**

- 에셋은 `files` 스토어의 `assets/<name>`에 Blob으로 저장한다. 분석 결과는 같은 레코드의 `meta`에 둔다. 따로 스토어를 만들지 않아서 DB 버전은 2 그대로다.
- 파일 이름은 폴더·따옴표·제어 문자를 빼고 공백을 `-`로 바꾼다(`sanitizeAssetName`). 그다음 겹치면 `-2`, `-3`을 붙인다.
- 업로드 경로는 셋이다. 창 어디에나 끌어다 놓기(씬 iframe이 드래그 이벤트를 가져가므로 창 전체를 덮는 오버레이로 받는다), 입력창의 클립 버튼, 오른쪽 패널의 Assets 탭이다.
- 업로드한 에셋은 다음 프롬프트의 첨부가 된다. 입력창 위에 칩으로 보이고 ×로 뺄 수 있다. 보낼 때는 `[Studio note]`로 이름과 메타데이터를 알리고, 이미지는 1024px로 줄여 image 블록으로 붙인다.
- 메타데이터: 이미지는 크기, 영상·오디오는 길이(영상은 해상도도), glTF/GLB/OBJ는 정점·면·메시 수와 경계 상자, SVG는 width/height 또는 viewBox, 텍스트는 줄 수, JSON은 최상위 구조다. 분석이 실패해도 업로드는 되고 `meta.error`에 이유를 남긴다.
- `asset_read`는 텍스트 계열(JSON, CSV, 셰이더, SVG, OBJ, glTF JSON)만 읽는다. 한 번에 최대 100,000자이고 `offset`으로 이어 읽는다. 바이너리를 요청하면 씬에서 쓰는 방법을 알려 준다.
- `ctx.utils.createVideoTexture(name)`는 첫 프레임이 준비되면 resolve한다. `update()`는 `requestVideoFrameCallback`으로 새 프레임이 있을 때만 업로드한다. 씬이 바뀌면 영상을 멈추고 해제한다.
- 씬 CSP의 `font-src`에 `blob:`을 더했다. 업로드한 폰트를 `FontFace`로 쓰기 위해서다.
- smoke에서는 파일 선택으로 파란 8x8 PNG와 JSON을 올린다. 목 에이전트는 첨부 노트·이미지 블록을 확인하고 `asset_list`, `asset_read`를 호출한다. 고친 씬은 그 PNG를 텍스처로 칠해서 에셋이 iframe까지 전달되는지 본다.

## 3. 타임라인·키프레임

- **형식:** 씬에 추가하는 필드다(v2 하위 호환, 기본값 있음).
  ```jsonc
  "timeline": { "duration": 10, "loop": true },
  "keyframes": { "u_speed": [{ "time": 0, "value": 1 }, { "time": 5, "value": 3, "ease": "easeInOut" }] }
  ```
  - float/int 유니폼만 받는다. 벡터·색은 성분별 키프레임으로 다음에 확장한다.
- **런타임:**
  - v1 `KeyframeManager.js`(순수 Hermite 보간)를 `scene/gl/`로 옮긴다.
  - 매 프레임 render 전에 키프레임 값을 `ctx.uniforms`에 넣는다. 사용자가 슬라이더를 직접 움직이면 그 유니폼은 키프레임보다 우선한다.
  - `timeline.duration`과 `loop`에 따라 시간을 감는다.
  - 루프할 때 상태가 있는 씬(시뮬레이션)을 어떻게 할지는 v1처럼 `preserveStateOnLoop`를 둘지 정한다. 기본은 setup을 다시 실행하는 것이다.
- **RPC:** `transport`에 `seek`가 이미 있다. 런타임 `stats` 이벤트로 현재 시간을 받는다.
- **UI:** 뷰포트 아래에 타임라인 바를 둔다. 재생/정지, 스크럽, 길이, 루프, 키프레임 점을 보여 준다. 슬라이더 옆에 "키 추가" 버튼을 둔다.
- **도구:** `scene_edit`에 `timeline`과 `keyframes` 필드를 추가한다(새 도구보다 낫다).
- **실행 취소:** 이참에 컨트롤과 키프레임 변경에 undo/redo(Cmd+Z)를 넣는다. 버전 히스토리와는 별개로, 세션 메모리에 둔다.

**구현 메모 (완료):**

- **모드 두 개:** 씬마다 Live(타임라인 없음, 기본)와 Timeline 중 하나다.
  - 원칙은 "UI는 준비돼 있되 필수는 아니다"이다. Live에서는 뷰포트 아래에 재생/정지와 경과 시간만 보이고, 슬라이더에 키 버튼이 없다.
  - Timeline에서만 스크럽 트랙, 키 마크, 길이·루프 메뉴, 슬라이더 옆 ◇/◆ 키 버튼이 나온다.
  - 전환은 바 오른쪽 `Live / Timeline` 스위치로 한다. Live로 돌아가면 타임라인과 키를 지우고(확인 창), Cmd+Z로 되돌릴 수 있다.
  - Timeline 모드에서도 마우스 같은 상호작용은 그대로 동작한다. 모드는 파라미터가 시간에 따라 바뀌느냐만 정한다.
  - 에이전트는 기본으로 Live를 쓰고, 타이밍이 요청의 핵심일 때만 타임라인을 단다(프롬프트에 적었다).
- **보간:** `ease`는 그 키에 *도착하는* 구간의 모양이다. 기본 `smooth`는 Catmull-Rom 기울기의 Hermite 보간(v1 KeyframeManager 이식)이고, 양 끝 키의 기울기는 0이다. 그 밖에 `linear`, `easeIn`, `easeOut`, `easeInOut`, `step`이 있다. int 유니폼은 반올림한다.
- **루프:** 기본은 끝에서 씬을 다시 로드해 setup을 다시 실행한다. 시뮬레이션이 키프레임과 다시 맞게 하려는 것이다. `preserveStateOnLoop: true`이면 시간만 감는다. 루프하지 않는 타임라인은 끝에서 멈추고, 재생을 누르면 처음부터 다시 한다.
- **키 편집은 다시 로드하지 않는다.** 새 RPC `setTimeline`이 런타임의 트랙만 바꾼다.
  - 키프레임이 있는 슬라이더를 직접 움직이면 그 유니폼은 오버라이드되어 키를 무시한다. 키를 바꾸면 오버라이드가 풀린다.
  - "키 추가"는 런타임에서 받은 정확한 재생 위치(0.01초 단위)에 현재 표시값으로 키를 만든다. 1/30초 안에 키가 있으면 그 키를 지운다.
- **stats 이벤트**를 250ms에서 100ms 간격으로 바꿨다. 플레이헤드와 애니메이션되는 슬라이더 값이 부드럽게 보이게 하려는 것이다.
- **undo/redo**는 유니폼 값, 타임라인, 키프레임, 오버라이드의 스냅숏 스택이다(최대 100단계). 같은 대상을 800ms 안에 연달아 바꾸면(슬라이더 드래그) 한 단계로 묶는다. 에이전트의 씬 변경이나 버전 복원은 스택을 비운다. 그 단계는 히스토리로 되돌린다.
- smoke에서는 목 에이전트가 `scene_edit`로 타임라인과 키프레임을 추가하고, 타임라인 바에 키 마크 2개와 `4s · loop`가 보이는지 확인한다.
- smoke가 `app.exit()`로 끝나면서 `before-quit`을 건너뛰어 허브 Python 프로세스가 매번 남던 문제도 고쳤다. 맥 실기 검증에서 발견했다.

## 3.5 `ask_user` (완료)

- 내장 에이전트 전용 도구다. 질문 하나와 선택지 2~4개를 받는다. 실행은 답을 받을 때까지 기다린다.
- 채팅에 선택지 버튼 카드가 뜬다. 입력창에 직접 쓴 답도 받는다. 중지하면 "답 없음" 에러 결과가 돌아간다.
- 지난 질문은 채팅 기록에 질문과 답으로 남는다.
- 프롬프트에서는 "만들 결과가 달라질 만큼 모호할 때만, 만들기 전에 한 번"으로 제한했다. 나머지는 에이전트가 정하고 무엇을 골랐는지 말한다.
- smoke에서는 목 에이전트가 질문하고, smoke가 버튼을 눌러 답한다(`questionShown`, `questionAnswered`).

## 4. 에이전트 패널(확장 컨트롤)

v1에는 패널 방식이 셋 있었다: JSON 컨트롤, 임의 HTML iframe, URL. M2에서는 **선언형을 먼저** 만든다.

- **선언형(우선):** 유니폼 정의에 `widget` 힌트를 추가한다.
  - `slider`(기본), `knob`, `pad`(vec2), `select`(`options: [{label, value}]`, int), `button`(bool 펄스: 누른 프레임에만 true), `curve`는 나중으로 미룬다.
  - 그룹 레이아웃은 `controls: [{ label, uniforms: [...] }]`로 한다(선택, 없으면 지금처럼 평면).
  - 모니터는 씬이 `ctx.publish(name, value)`로 값을 내보내고, 런타임이 이벤트로 스로틀해 전달하면 패널에 숫자나 스파크라인으로 보여 준다. 에이전트가 "FPS나 입자 수를 보여줘"를 처리할 수 있다.
- **HTML 패널(그다음):** 에이전트가 쓴 HTML/JS는 `srcdoc` + `sandbox="allow-scripts"`(opaque origin) iframe에서만 돌린다.
  - postMessage는 targetOrigin `"*"` + 수신 측 `e.source` 확인으로 한다. v1은 opaque origin과 출처를 비교하다가 브리지가 깨져 있었다.
  - 패널은 유니폼 설정과 publish 값 구독만 할 수 있다.
- URL 패널은 만들지 않는다.

**구현 메모 (선언형 완료):**

- 유니폼에 `widget`을 둔다. `slider`, `knob`(float/int, 위아래로 드래그하고 Shift는 미세 조정), `pad`(vec2, x는 오른쪽, y는 위쪽, min/max는 두 축에 공통), `select`(int/float, `options` 필수), `toggle`(bool), `button`(bool 펄스)이다. 타입이 맞지 않으면 어떤 타입이 필요한지 에러로 알려 준다.
- `button`은 누른 뒤 렌더된 첫 프레임에만 true이고 그다음 false로 돌아간다. 편집이 아니므로 undo와 버전을 만들지 않는다.
- `controls` 그룹이 있으면 그룹 순서대로 보여 주고, 빠진 유니폼은 "Other"에 둔다. 그룹이 없으면 지금처럼 평면 목록이다. `scene_edit`의 `controls`로 바꾸거나(null이면 제거) 할 수 있고, 유니폼을 지우면 그룹에서도 빠진다.
- 모니터는 `ctx.publish(name, value)`로 내보낸다. 값은 숫자, 문자열, 불리언이고 최대 32개, 문자열은 200자까지다. 런타임은 바뀐 값만 stats 주기(100ms)에 `monitors` 이벤트로 보낸다. 패널은 숫자에 최근 60개 값의 스파크라인을 붙인다. 씬을 로드하면 비운다.
- smoke에서는 목 씬이 노브, 버튼, 그룹, 모니터(`frames`, `bursts`)를 쓴다. 버튼을 두 번 누르면 `bursts`가 정확히 2가 되는지 본다.
- smoke에 단계별 진행 로그(`[smoke] 1.8s agent replied`)를 넣었다. 한 번 원인 모를 시간 초과가 있었고 이후 재현되지 않았다. 다시 나면 로그로 멈춘 단계를 찾는다.
- **HTML 패널은 2단계 뒤로 미룬다.** 외부 에이전트 연결이 들어오면 패널 API(유니폼 설정, publish 구독)를 그 설계와 함께 정하는 편이 낫다.

## 5. WebGPU 백엔드

- **런타임:** `scene.backend === "webgpu"`이면 load마다 새 `GPUDevice`를 요청한다(이전 것은 `destroy()`).
  - 캔버스 `webgpu` 컨텍스트를 `navigator.gpu.getPreferredCanvasFormat()`로 설정한다.
  - ctx에 `device`, `context`, `format`을 넣고, WebGL 전용 헬퍼는 넣지 않는다.
- **에러:**
  - `createShaderModule` 후 `getCompilationInfo()`의 메시지(lineNum, linePos)를 `ShaderError`와 같은 구조로 바꾼다. 헬퍼 `ctx.utils.createShaderModule(code)`를 쓰게 한다.
  - setup은 `pushErrorScope('validation')`로 감싼다. 렌더 중에는 N프레임마다 error scope를 쓰고, `uncapturederror`와 `device.lost`를 SceneError로 보낸다.
- **캡처:** submit 직후 같은 task에서 `createImageBitmap(canvas)`를 쓴다. 맥과 윈도우에서 실제로 되는지 확인하고, 안 되면 `copyTextureToBuffer`로 대체한다.
- **프롬프트:** WGSL을 직접 쓰게 한다. v1의 GLSL→WGSL 변환기는 다시 들이지 않는다.
- smoke의 Linux(SwiftShader)에서 WebGPU가 안 되면, 그 검사는 플랫폼별로 건너뛰게 표시한다.
