# M2 계획: v1 핵심 기능을 studio로

> 상태: 착수 전 · 2026-10
> 전제: [studio.md](studio.md)(M1 구조), 루트 `CLAUDE.md`(지켜야 할 규칙)

## 0. 시작 전에: M1 실기 검증

M1은 Linux 컨테이너에서 목(mock) API로만 검증했다. M2를 시작하기 전에 다음을 확인한다.

1. macOS(Apple Silicon)에서 `npm install` → `npm run check && npm test && npm run smoke`를 실행한다.
2. `npm run dev`로 띄워서 **실제 API 키**로 프롬프트 3~5개를 돌린다. 예: 파도 셰이더, 마우스로 흔드는 반응-확산(핑퐁 버퍼), 레이마칭 구체, 텍스처를 쓰는 씬.
3. 실패 패턴을 기록하고 `agent/prompt.ts`와 도구 설명을 다듬는다. 자주 틀리는 ctx 사용법, 캡처 확인을 건너뛰는지, 같은 수정을 반복하는지를 본다.
4. `npm run dist`로 dmg를 만들고 패키징된 앱의 smoke도 돌린다.

여기서 나온 버그 수정은 M2보다 먼저 한다.

**결과 (2026-10-11, macOS 26 / Apple M5, Node 25, npm 11):**

- 1번 통과. `npm install` 후 `check`, `test`(vitest 19개, pytest 6개), `smoke`(체크 10개, 목 요청 4회) 모두 통과했다. smoke 보고서의 CSP 콘솔 에러 2건은 씬 iframe이 포워더에 접근하려다 막히는 검사(`llmRefusesScene`)에서 나오는 것으로, 의도된 동작이다.
- 4번 통과. `npm run dist`로 `Siljangnim-0.2.0-mac-arm64.dmg`를 만들었다(ad-hoc 서명, 공증 없음). 패키징된 앱으로 돌린 smoke(`SILJANGNIM_APP_PATH=release/mac-arm64/Siljangnim.app/Contents/MacOS/Siljangnim`)도 모든 체크를 통과했다.
- 2·3번(실제 API 키로 프롬프트 실행, 프롬프트 다듬기)은 보류했다. M2를 먼저 진행하고, 이후 따로 한다.

## 작업 순서

에이전트의 수정을 되돌릴 수 있는 안전망부터 만든다. 그다음은 사용 빈도 순이다.

| # | 기능 | 이유 |
|---|---|---|
| 1 | 버전 히스토리 | 에이전트가 씬을 망쳐도 되돌릴 수 있어야 실험이 편하다 |
| 2 | 에셋 업로드 | 이미지·영상·오디오를 쓰는 작업이 많다 |
| 3 | 타임라인·키프레임 | 애니메이션과 이후 녹화(M3)의 바탕이다 |
| 4 | 에이전트 패널(확장 컨트롤) | 유니폼 컨트롤만으로 부족한 UI |
| 5 | WebGPU 백엔드 | compute가 필요한 씬. 수요가 가장 적다 |

기능마다 완료 기준은 같다.

- `check`, `test`, `smoke`가 통과한다.
- 로직에 단위 테스트가 있다.
- 에이전트가 쓰는 기능이면 smoke의 목 시나리오에서 실제로 호출해 본다.
- 문서를 갱신하고 커밋을 따로 남긴다.

## 1. 버전 히스토리

- **모델:** 커밋 트리. `{ id, projectId, parentId, createdAt, message, scene, thumbnail?, chatLength }`
  - `scene`은 전체 JSON 스냅샷이다. 씬은 수 KB라 패치·체크포인트 방식은 쓰지 않는다. v1 projectTree의 복잡도를 반복하지 않는다.
  - `chatLength`는 그 시점의 메시지 수다. 대화와 버전을 연결한다.
- **저장:** IndexedDB `versions` 스토어(인덱스 `byProject`). `ProjectStore`의 DB 버전을 2로 올리고 upgrade에서 스토어를 추가한다. 기존 데이터 마이그레이션 테스트를 쓴다.
- **언제 만드나:**
  - 에이전트 실행이 끝났을 때. message는 사용자 프롬프트의 앞부분으로 한다.
  - 사용자가 컨트롤을 만지다 멈췄을 때(디바운스). 직전 버전과 씬이 같으면 만들지 않는다.
- **썸네일:** 버전을 만들 때 `capture`를 256px로 찍어 Blob으로 저장한다. 실패하면 썸네일 없이 저장한다.
- **복원:** 버전을 고르면 그 씬을 적용하고 HEAD를 옮긴다. 이후 변경은 그 버전의 자식이 되어 브랜치가 생긴다.
  - 대화는 append-only이므로 되감지 않는다.
  - 대신 복원할 때 다음 사용자 메시지 앞에 "버전 X로 되돌렸다"는 맥락을 붙인다. 시스템 프롬프트는 바꾸지 않는다.
- **UI:** 오른쪽 패널에 탭 하나(채팅 | 히스토리). 썸네일 목록에 부모 관계를 들여쓰기로 표시하는 정도면 충분하다.
- **도구(선택):** `history_list`, `history_restore`. 에이전트가 "아까 버전이 나았다"를 처리할 수 있게 한다.

## 2. 에셋 업로드

- **입력:** 뷰포트나 채팅에 드래그 앤 드롭, 또는 파일 선택. 이미지, 영상(mp4/webm), 오디오, 폰트, SVG, JSON/텍스트, glb/obj를 받는다.
- **저장:** `files` 스토어에 `assets/<name>` Blob으로 둔다.
  - 이름이 겹치면 `name-2.png`처럼 바꾼다.
  - 크기 상한은 우선 200MB/파일로 하고 UI에서 거절한다.
- **런타임 전달:** 이미 지원한다(`load`의 `assets` → `ctx.assets[name]` blob URL). 씬을 로드할 때 프로젝트 에셋 전체를 넘긴다. 큰 에셋이 많아지면 나중에 씬이 참조하는 것만 넘기도록 최적화한다.
- **메타데이터:** 업로드할 때 가볍게 분석한다. 이미지는 크기, 영상·오디오는 길이와 해상도, 3D는 정점 수다. v1 `assetProcessor.js`에서 필요한 부분만 가져온다.
- **에이전트에게:**
  - `asset_list` 도구: 이름, 종류, 크기, 메타데이터를 돌려준다.
  - 이미지를 프롬프트와 함께 올리면 축소본(최대 1024px)을 사용자 메시지에 image 블록으로 붙인다(비전).
  - 텍스트·JSON은 `asset_read`로 읽는다(크기 제한).
- **ctx:** `ctx.utils.loadTexture(name)`는 이미 에셋 이름을 받는다.
  - 영상 텍스처 헬퍼(`createVideoTexture(name)` → 매 프레임 `update()`)를 추가한다.
  - glTF/OBJ 로더는 B등급 온디맨드 원칙에 따라 에이전트가 `ctx.utils.import`로 받아 쓰게 두고, 프롬프트에 방법을 적는다.
- **보안:** 에셋은 Blob으로만 넘긴다. SVG는 `<img>`/텍스처로만 쓰고 DOM에 삽입하지 않는다.

## 3. 타임라인·키프레임

- **형식:** 씬에 추가하는 필드다(v2 하위 호환, 기본값 있음).
  ```jsonc
  "timeline": { "duration": 10, "loop": true },
  "keyframes": { "u_speed": [{ "time": 0, "value": 1 }, { "time": 5, "value": 3, "ease": "easeInOut" }] }
  ```
  - float/int 유니폼만 받는다. 벡터·색은 성분별 키프레임으로 다음에 확장한다.
- **런타임:**
  - v1 `KeyframeManager.js`(순수 Hermite 보간)를 `scene/gl/`로 옮긴다.
  - 매 프레임 render 전에 키프레임 값을 `ctx.uniforms`에 넣는다. 사용자가 슬라이더를 직접 움직이면 그 유니폼은 키프레임보다 우선한다.
  - `timeline.duration`과 `loop`에 따라 시간을 감는다.
  - 루프할 때 상태가 있는 씬(시뮬레이션)을 어떻게 할지는 v1처럼 `preserveStateOnLoop`를 둘지 정한다. 기본은 setup을 다시 실행하는 것이다.
- **RPC:** `transport`에 `seek`가 이미 있다. 런타임 `stats` 이벤트로 현재 시간을 받는다.
- **UI:** 뷰포트 아래에 타임라인 바를 둔다. 재생/정지, 스크럽, 길이, 루프, 키프레임 점을 보여 준다. 슬라이더 옆에 "키 추가" 버튼을 둔다.
- **도구:** `scene_edit`에 `timeline`과 `keyframes` 필드를 추가한다(새 도구보다 낫다).
- **실행 취소:** 이참에 컨트롤과 키프레임 변경에 undo/redo(Cmd+Z)를 넣는다. 버전 히스토리와는 별개로, 세션 메모리에 둔다.

## 4. 에이전트 패널(확장 컨트롤)

v1에는 패널 방식이 셋 있었다: JSON 컨트롤, 임의 HTML iframe, URL. M2에서는 **선언형을 먼저** 만든다.

- **선언형(우선):** 유니폼 정의에 `widget` 힌트를 추가한다.
  - `slider`(기본), `knob`, `pad`(vec2), `select`(`options: [{label, value}]`, int), `button`(bool 펄스: 누른 프레임에만 true), `curve`는 나중으로 미룬다.
  - 그룹 레이아웃은 `controls: [{ label, uniforms: [...] }]`로 한다(선택, 없으면 지금처럼 평면).
  - 모니터는 씬이 `ctx.publish(name, value)`로 값을 내보내고, 런타임이 이벤트로 스로틀해 전달하면 패널에 숫자나 스파크라인으로 보여 준다. 에이전트가 "FPS나 입자 수를 보여줘"를 처리할 수 있다.
- **HTML 패널(그다음):** 에이전트가 쓴 HTML/JS는 `srcdoc` + `sandbox="allow-scripts"`(opaque origin) iframe에서만 돌린다.
  - postMessage는 targetOrigin `"*"` + 수신 측 `e.source` 확인으로 한다. v1은 opaque origin과 출처를 비교하다가 브리지가 깨져 있었다.
  - 패널은 유니폼 설정과 publish 값 구독만 할 수 있다.
- URL 패널은 만들지 않는다.

## 5. WebGPU 백엔드

- **런타임:** `scene.backend === "webgpu"`이면 load마다 새 `GPUDevice`를 요청한다(이전 것은 `destroy()`).
  - 캔버스 `webgpu` 컨텍스트를 `navigator.gpu.getPreferredCanvasFormat()`로 설정한다.
  - ctx에 `device`, `context`, `format`을 넣고, WebGL 전용 헬퍼는 넣지 않는다.
- **에러:**
  - `createShaderModule` 후 `getCompilationInfo()`의 메시지(lineNum, linePos)를 `ShaderError`와 같은 구조로 바꾼다. 헬퍼 `ctx.utils.createShaderModule(code)`를 쓰게 한다.
  - setup은 `pushErrorScope('validation')`로 감싼다. 렌더 중에는 N프레임마다 error scope를 쓰고, `uncapturederror`와 `device.lost`를 SceneError로 보낸다.
- **캡처:** submit 직후 같은 task에서 `createImageBitmap(canvas)`를 쓴다. 맥과 윈도우에서 실제로 되는지 확인하고, 안 되면 `copyTextureToBuffer`로 대체한다.
- **프롬프트:** WGSL을 직접 쓰게 한다. v1의 GLSL→WGSL 변환기는 다시 들이지 않는다.
- smoke의 Linux(SwiftShader)에서 WebGPU가 안 되면, 그 검사는 플랫폼별로 건너뛰게 표시한다.

## 하지 않는 것 (M3 이후)

- 녹화(MP4/WebM/PNG), 오디오·마이크·MIDI·OSC·MediaPipe 입력, v1 프로젝트 가져오기 → M3
- MCP 서버, 레시피, 온디맨드 오픈소스 런타임 → 2단계 이후([architecture.md](architecture.md))
- 웹 배포 전환 → M3 이후
