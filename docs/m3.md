## 1. 녹화

- **위치:** 캔버스가 씬 iframe에 있으므로 녹화도 런타임에서 한다. 앱은 `record` RPC로 요청하고 진행률(`recording` 이벤트)을 받는다. 결과 Blob을 받아 **프로젝트 에셋으로 저장하고 다운로드**한다(`recording-YYYYMMDD-HHMMSS.mp4` 등).
- **오프라인(기본):** 정확하고 매끄러운 결과를 내는 모드다.
  - 씬을 처음부터 다시 로드한다(시뮬레이션도 t=0부터). 출력 크기로 캔버스를 고정한다. 이 동안 rAF 루프의 렌더를 멈추고 녹화기가 `t = f / fps`에서 한 프레임씩 그린다.
  - 기계가 느려도 결과는 같다. 키프레임도 정확한 시각에 평가된다.
  - MP4는 H.264(안 되면 HEVC), WebM은 VP9(안 되면 VP8)로 WebCodecs를 거쳐 인코딩하고, 컨테이너는 **mediabunny** 1.60.0으로 만든다. v1의 mp4-muxer·webm-muxer는 지원이 끝났고 mediabunny가 그 후속이다. 인코딩할 수 없는 코덱이나 크기면 이유를 에러로 알려 준다.
  - H.264 때문에 크기는 짝수로 내린다.
  - PNG는 프레임마다 PNG를 만들어 무압축 zip(`scene/runtime/zip.ts`) 하나로 묶는다. PNG는 이미 압축돼 있어 압축 라이브러리가 필요 없다.
- **실시간:** `canvas.captureStream` + MediaRecorder(WebM)로, 마우스 같은 상호작용을 그대로 담는다. 정한 길이가 되거나 Stop을 누르면 끝난다.
- **길이:** 타임라인이 있으면 그 길이, 없으면 5초가 기본이다. UI와 도구 모두 바꿀 수 있다.
- **UI:** 뷰포트 아래 바의 `● Rec` → 모드, 형식, 크기(뷰포트 / 1080p / 720p / 정사각 / 세로), FPS, 길이, 품질을 고른다. 녹화하는 동안 뷰포트 위에 진행률과 취소 버튼이 뜬다.
- **에이전트:** `viewport_record` 도구가 있다(외부 에이전트도 같음). 녹화는 씬을 바꾸지 않으므로 버전을 만들지 않는다.
- **검증:**
  - 단위 테스트: zip 형식(CRC-32, 디렉터리), 도구 기본값
  - MCP smoke(보이는 Electron 창): MP4(320×240, 1초), PNG 프레임 zip, 실시간 WebM을 녹화한다. MP4가 영상으로 해석되는지(`video 320x240 1.00s`)와 세 파일이 다운로드됐는지 확인한다.
  - WebGPU 예제도 MP4로 녹화된다(`mcp/scripts/capture-scene.mjs`에 `SILJANGNIM_RECORD=mp4`).
- 데스크톱 앱에서 다운로드는 Electron 기본 동작인 저장 대화상자를 거친다.

## 2. 입력

- 씬마다 `SceneInputs` 하나가 load와 함께 생기고 unload 때 연 것을 모두 닫는다(`scene/runtime/inputs.ts`). 값을 계산하는 순수 부분은 `inputData.ts`에 있고 단위 테스트가 있다.
- **오디오:** `ctx.audio` = `{ active, source, level, bass, mid, treble, spectrum[256], waveform[512] }`. 매 프레임 렌더 전에 갱신한다.
  - 마이크: `inputs: ["microphone"]`이면 씬과 함께 시작하고, `ctx.utils.audio.useMicrophone()`으로도 켤 수 있다.
  - 파일: `ctx.utils.audio.play(asset, { loop, volume, output })`. `output: false`면 소리 없이 분석만 한다.
  - WebGL에서는 `u_audio`(vec4: level, bass, mid, treble)가 표준 유니폼이 되고, `ctx.utils.audioTexture()`가 256×2 R32F 텍스처(0행 스펙트럼, 1행 파형)를 매 프레임 갱신한다. WebGPU는 `createUniforms()`의 struct에 `audio: vec4f`가 들어간다.
  - 스펙트럼은 AnalyserNode(fft 1024)의 dB 값을 -100~-20 dB 구간에서 0..1로 바꾼다. 대역은 bass 20–250 Hz, mid 250–4000 Hz, treble 4–16 kHz다.
  - 브라우저가 자동 재생을 막으면 뷰포트를 클릭할 때 재개한다.
- **MIDI:** `ctx.midi` = `{ cc[128], notes[128](세기 0..1), lastNote, pitchBend }`. `inputs: ["midi"]`나 `ctx.utils.enableMidi()`로 켜면 모든 장치를 연결하고, 장치를 꽂고 뽑아도 다시 묶는다.
- **카메라:** WebGL은 `ctx.utils.createCameraTexture()`이고 비디오 텍스처와 같은 모양(`update()`)이다. WebGPU는 `ctx.utils.cameraVideo()`로 `<video>`를 받아 `importExternalTexture`에 쓴다. 비디오 텍스처 헬퍼는 이제 MediaStream도 받는다. 스트림은 재생해야 첫 프레임이 와서 바로 재생한다(이걸 빠뜨려 setup이 멈추던 문제를 고쳤다).
- **에이전트가 값 확인:** `viewport_status`가 씬이 publish한 모니터 값을 함께 보여 준다.
- **예제 `audio-bars`:** 합성한 음악 루프(`assets/beat.wav`, 8초)로 스펙트럼 막대, 베이스 링, 파형을 그린다.
- **검증:**
  - MCP smoke: Chromium의 가짜 카메라(640 확인)와, 씬이 만든 110 Hz 톤의 분석(bass ≈ 0.8, level > 0)
  - 데스크톱 smoke: `audio-bars`를 포함한 예제 전체를 렌더한다. 소리는 음소거하고 분석은 그대로 한다.
  - **macOS에서 Electron의 가짜 마이크는 `getUserMedia`가 응답하지 않는다**(실제 마이크는 OS 권한을 거친다). 그래서 자동 테스트는 파일 분석으로 오디오 경로를 확인한다. 마이크 경로는 같은 AnalyserNode 코드를 쓴다.
- **OSC:** 브라우저는 UDP를 받을 수 없어서 허브가 받는다(`hub/siljangnim_hub/osc.py`).
  - 씬이 `inputs: ["osc"]`(포트 9000)나 `ctx.utils.listenOsc(port)`로 요청하면 런타임이 `oscListen` 이벤트를 보낸다. 앱이 허브에 `POST /osc/listen`을 보내고 `GET /osc/stream`(SSE)을 연다. 받은 메시지는 `osc` RPC로 씬에 넘긴다. 토큰은 헤더로 보내므로 EventSource 대신 fetch 스트림을 읽는다.
  - `ctx.osc` = `{ active, port, values{주소: 인자들}, messages(이번 프레임), last, get(주소, index, fallback) }`. 메시지와 번들(i f s b h d t T F N I)을 지원하고 번들 시각은 무시한다.
  - 리스너는 0.0.0.0에 열어 같은 네트워크의 폰이나 다른 기계에서 보낼 수 있다. OSC를 쓰지 않는 씬을 로드하면 닫는다. OSC를 쓰는 씬끼리는 다시 로드해도 열린 채로 둔다. 스트림이 끊기면 1초 뒤 다시 연결한다. 포트가 이미 쓰이고 있으면 씬 에러(`OSC: can't listen on UDP …`)로 알린다.
  - 허브가 필요하므로 데스크톱 앱이나 MCP 브리지에서만 동작한다. 그냥 브라우저에서는 이유를 에러로 알린다.
  - 검증: hub pytest(파싱, 번들, 잘못된 데이터, 실제 UDP 수신, 포트 충돌)와 studio 단위 테스트(`get`, 프레임별 메시지). MCP smoke는 node `dgram`으로 `/fader 0.75`와 `/label "hello"`를 실제 UDP로 보내 씬 모니터에서 `oscFader=0.75, oscText=hello, oscCount=2`를 확인한다.
- **MediaPipe(손·얼굴·포즈·분할):** 번들하지 않는다. 씬이 `ctx.utils.import`로 `@mediapipe/tasks-vision@1.0.1`을 jsdelivr에서, 모델은 Google 저장소에서 필요할 때 받는다. 프롬프트에 사용법을 넣었다(새 카메라 프레임마다 `detectForVideo`, y는 아래로 증가, 화면은 거울처럼, 점은 vec2 배열 유니폼, cleanup에서 `close()`).
  - 예제 `hand-tracking`: 거울처럼 비친 웹캠 위에 두 손의 랜드마크 42개를 빛나는 점으로 그리고 `hands` 수를 publish한다. `requires: ["camera", "network"]`라서 갤러리에 Camera 배지가 붙는다.
  - 검증: Electron 뷰어(가짜 카메라)에서 WASM·모델을 받아 에러 없이 돌고 `hands=0` 모니터가 나오는 것까지 확인했다. 가짜 영상에는 손이 없다. 썸네일은 같은 셰이더에 손 모양 좌표를 넣어 찍었다.
  - 데스크톱 smoke는 카메라와 네트워크가 필요한 예제를 건너뛴다(테스트 기계에 있다고 가정할 수 없다).
- smoke가 실패해 종료될 때 Electron 뷰어가 남아 다음 실행의 `viewer.json`을 덮어쓰던 문제를 고쳤다. 이제 항상 종료 시 정리한다.

## 3. v1 프로젝트 가져오기

- 프로젝트 메뉴의 **Import v1 project (.zip)…**에서 v1이 내보낸 zip(`<이름>/siljangnim-project.json`, `scene.json`, `panels.json`, `uploads/…`)을 새 프로젝트로 연다(`project/v1Import.ts`).
- zip은 직접 읽는다. 무압축(STORE)과 DEFLATE를 지원하고, DEFLATE는 브라우저의 `DecompressionStream("deflate-raw")`로 푼다.
- **씬:** v1 스크립트 씬은 `parseScene`의 v1 변환을 거친다. v1 스크립트가 쓰던 `ctx.uploads`는 v2에서 `ctx.assets`와 같은 객체로 남겨 그대로 동작한다.
- **컨트롤:** `panels.json`의 controls 패널을 v2 유니폼 정의로 옮긴다.
  - slider → float/int(범위, step, 라벨, 기본값), color(hex, 알파 포함) → color vec4, toggle → bool, button → 버튼 위젯, dropdown → select, pad2d → vec2 패드, vec3 → vec3
  - separator/group은 v2 `controls` 그룹이 된다.
- **옮기지 않는 것**은 가져온 뒤 안내하고, 다음 프롬프트에 에이전트용 `[Studio note]`로 붙인다.
  - 채팅 기록: v2 대화는 API 형식이라 그대로 넣을 수 없다.
  - v1 버전 노드
  - HTML/URL 패널
  - v2에 대응이 없는 컨트롤(monitor, graph, preset 등)
  - 공백이 바뀐 업로드 이름
- **검증:**
  - 단위 테스트: STORE·DEFLATE 항목, 씬·컨트롤·그룹·업로드 변환, 안내 문구
  - 데스크톱 smoke: v1 형식 zip을 실제 메뉴의 파일 입력으로 가져와, 프로젝트가 열리고 에러 없이 렌더되는지(`ctx.uploads` 확인 포함), 슬라이더 값이 옮겨졌는지 본다.
- smoke가 찾아낸 앱 버그를 고쳤다. 가져오기용 파일 입력이 프로젝트 메뉴 안에만 있어서, 메뉴가 닫히면 고른 파일이 무시될 수 있었다. 이제 입력은 메뉴 밖에 항상 있다.
- smoke에서 시나리오가 예외를 던지면 시간 초과를 기다리지 않고 단계와 이유를 바로 보고한다.
